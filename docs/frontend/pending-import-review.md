# Reopening an unfinished CV review across browsers

The import screen delegates operation identity, bounded reads/polling, recovery and cancellation to `apps/web/src/base/useImportSession.ts`. The session lifetime follows the stable authenticated transport identity, so ordinary client-wrapper recreation does not interrupt a pending poll or cancellation. Public receipt types and validation are shared in `packages/contracts/src/intelligence/import-status.ts`; ready discovery metadata is distinct from a validated review body. Presentation, review selection, additive merging and Profile persistence keep their existing owners. [Browser timing](../setup/cv-import-timing.md) is diagnostic only and cannot mark a review confirmed or a Profile saved.

Opening or refreshing My Profile checks the authenticated account for its newest unconfirmed, unexpired ready import. Discovery does not depend on a browser's last URL, local storage or an edited workspace draft. The read-only `GET /v1/intelligence/imports/pending` endpoint returns receipt metadata; the existing import endpoint then opens the source review, and its account-backed `import-review` workspace draft restores acknowledged corrections and selections.

Only opening My Profile or the application root triggers account discovery. Direct links to history, enrichment and specific pending imports keep their destination. Pending review metadata takes precedence over stale last-visited import URLs. Late responses cannot override navigation chosen during discovery, and the initial check is bounded to 15 seconds. React Strict Mode cancels superseded reads and starts replacement reads normally.

A successful Profile publication appends the existing `review_decisions` receipt in the same database transaction. Only that committed receipt excludes the review from discovery; staged review autosaves and failed publication attempts do not. A stale link to the import currently confirmed in the saved Profile returns to My Profile. Explicit confirmation remains required before any imported data becomes the Profile.

The initial review's former navigation label is now **Discard review** / **Renunță la verificare**. Discarding an import review calls the existing authenticated cancellation endpoint before leaving the screen. The local review save controller is disposed, and server cancellation excludes the review for every browser. Failed cancellation retains the review and shows an error. Neither discovery nor reopening starts a new upload or AI request.

Migration `20261031194408_pending_cv_import_review.sql` adds only `app.get_pending_cv_import()` and is applied to the existing Resumora development database. It filters through `tenant_for_user()`, ready state, live expiry and an empty committed-decision array, returns no review body, and grants execution only to authenticated users. The static advisor reports the intentionally authenticated SECURITY DEFINER RPC ([explanation](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)); owner scoping and anonymous/foreign-account denials are covered by native SQL tests. No table, account credential or inference configuration is changed.

Verification uses synthetic data. Five PostgreSQL cases cover discovery without a staged draft, restored saved choices, account isolation, atomic publication success/failure, discard and expiry. Component journeys run under Strict Mode and reopen the same saved review in a new App/registry, restore corrected names, confirm/discard, preserve explicit destinations and bound stalled discovery. Session-fencing tests include the new metadata endpoint among retired-session requests that must never be delivered.

Playwright uses two independent browser contexts for the same synthetic account plus a third context for another account. Browser B opens My Profile before the upload; browser A uploads and corrects its review; browser B refreshes its original My Profile URL and restores that correction. A second upload into the existing Profile is also discovered by a real refresh in browser B without applying any updates. Confirmation and a separate additive-review discard prevent subsequent reopening. All API traffic is intercepted, only the two explicitly selected synthetic files are uploaded, and no real provider call or owner-CV write is made. Captures and machine-readable proof are in the conversation visualization directory under `pending-review-two-browsers/`.

Final checks: all 542 frontend tests, all 297 API tests and all five focused PostgreSQL tests passed. Web/API TypeScript checks, production web build and `git diff --check` passed. The local API health endpoint returns HTTP 200; unauthenticated pending-review discovery returns HTTP 401. The existing web bundle-size warning remains. No hosted Worker deployment was performed.
