# Experience writing assistant

The Profile now opens a focused whole-entry workspace for employment, projects and volunteering when the connected client exposes `experience`. The existing document/save controller remains authoritative. Legacy point edits and in-progress point sessions continue through `ExperienceEnrichment`; other optional section types keep their existing flow.

## Whole-entry flow — 2 November 2026

`ExperienceWorkspace` selects the appropriate view. `GuidedExperience` presents one primary action per step; `useGuidedExperience` owns feature-specific request/recovery behavior without replacing Profile persistence.

- The overview opens immediately, including when revisiting an accepted role. Select a feedback point to ask up to three contextual questions about that exact point, one at a time. The original text stays on the left, with score and actionable feedback on the right. Selecting either a text point or its feedback expands questions beneath that exact point; the right panel stays available. **Next question** confirms an answer; **See proposal** confirms the final answer and explicitly requests a rewrite using the updated evidence. Skipping does not request a rewrite. **Back to suggestions** preserves unfinished typing. Saved `rounds` retain point-specific sessions so switching points does not repeat inference or lose answers. **Improve your experience through questions** resumes unfinished answers or opens current point guidance. Confirmed answers remain reusable evidence; draft typing is not generation evidence. Questions include a compact contextual hint and an optional, clearly labeled illustrative example. Examples are display-only, never prefilled or confirmed as facts. General questions stay below the description rather than attaching to the last selected point.
- The labelled AI icon beside **Current description** requests one complete role proposal: a short introduction and concise responsibilities/achievements, using existing evidence. Whole-role generation requires all eligible facts to fit the existing 24-chunk/8,000-character bound; oversized contexts fail explicitly rather than silently dropping responsibilities.
- Live wording is marked **Drafting…**. Only a complete, validated result becomes an editable proposal. The original is behind **Show original**. **Use this version** explicitly accepts the whole text; successful Profile save is required before **Role saved**. Undo is guarded against subsequent changes.
- **Prepare a new version** replaces a stale proposal explicitly and retains the previous candidate until successful generation. Reopening pending work reads its existing receipt. If the request was saved but never dispatched, **Resume improvement** uses the original operation ID after a missing receipt; uncertain work is not automatically resubmitted. A settled `unknown` receipt stops automatic polling, leaves the overview accessible, and offers **Try again** as an explicit new attempt; it does not claim the interrupted operation is still generating.
- The `preview` intent assesses exact staged candidate text with the existing rubric. Editing invalidates the preview immediately. Only complete assessments with matching policy and feedback language receive a before/after comparison. Preview failure does not block acceptance. A 90+ score receives proportionate positive feedback without concealing weak points. Preview scores are writing assessments, not ATS pass probabilities.
- **Improve skills** extracts skills and then improves the full inventory. Responses contain names, categories, importance and cleanup tracking IDs; there are no supporting quotes or reference checks. The profile is locked through generation and saving. See [Improve skills](improve-skills.md) for the current contract and recovery behavior.

Employment, project and volunteering eligibility, visible fields and evidence are resolved together. Hidden fields, unaccepted facts and superseded answers are excluded. New proposals/candidates/recovery metadata stay inside the existing `experienceEnrichment` container, already stripped from frozen job copies. No database migration accompanies this extension.

An empty Profile role description also offers **Generate role summary with AI**. This reuses
the existing grounded summary service in the CV language: normally 3–5 sentences, fewer for
sparse evidence, capped at five sentences and 1,200 characters. The proposal is reviewed and
editable before acceptance. Acceptance fills only the still-empty role context, which renders
before its unchanged contribution bullets, then uses ordinary autosave. Late generation cannot
replace text the user typed meanwhile, and unrelated concurrent edits are preserved.

Whole-role citation coverage distinguishes existing CV responsibilities from coaching replies. Every chunk of the original CV evidence remains required. Confirmed replies are available as context, but uncertain, non-substantive or unrelated replies need not appear in the proposal or its citations. The model is instructed to incorporate useful supported details; all cited IDs and numeric claims remain validated. Answers are preserved even when omitted from the wording. Invalid whole-role output emits a bounded `experience_validation_failed` diagnostic containing the operation ID and failed rule only.

## Streaming and timing

The entry screen now shows the original description on the left and its current score and actionable feedback on the right (stacked on small screens). Feedback links highlight the corresponding original point and open its questions alongside the original and score. A high average only earns the “strong description” message when the priority point also clears the existing threshold.

Questions include an optional contextual `hint` generated in the same request. Hints suggest useful details or a response structure, never prefill or confirm an answer. Existing saved questions remain compatible and receive local guidance by question dimension. Voice typing supports live interim words where browser recognition is available, with a recorded fallback; it never confirms the answer. See [voice typing](../setup/voice-typing.md) for endpoint, accounting and verification limits.

Import reading and the pre-stream preparation stage use decorative animated document illustrations with reduced-motion support. These animations do not imply a percentage or processing milestone. Preparation is paused when the Profile save needs attention.

Interactive whole-role generation negotiates SSE through the existing authenticated experience endpoint. Both OpenRouter and the direct OpenAI fallback use their existing Chat Completions routes with streaming enabled. Provider parsing handles split UTF-8/JSON escapes, comments, usage-only frames, refusal, truncation and incomplete streams. Ordinary JSON responses and existing nonstreaming consumers remain supported.

Application events carry operation identity and ordered sequence numbers. `draft_delta` appends text, `draft_reset` replaces a provisional attempt, `ready` carries the canonical validated result, and `failed` carries a bounded error code. Text is not resent cumulatively on every token. The browser never joins partial primary output to fallback output. Observer disconnection does not own provider settlement; reconnect reads durable receipts without replaying inference. Partial text never becomes accepted wording or evidence.

Display pacing buffers delivery bursts and reveals about 33 characters per second without slowing provider requests, validation, result persistence or score previews. After readiness, the animation continues instead of abruptly exposing the entire proposal; **Show full text** skips straight to editing. Reduced-motion preferences bypass the animation. Failed requests clear provisional text, and a replacement attempt resets the display. Recovered proposals open directly for review.

The user target is normally 5–10 seconds and within 15 seconds to an actionable result; first readable output has a 2–3 second target. These are not measured hosted guarantees. The existing 25-second interactive safety deadline remains unchanged pending evidence for task-specific budgets. Scoring is separate from generation and cannot hold up a valid proposal.

Content-free `experience-timing` events distinguish stage reservation, provider round trip, validation and attempt settlement; the streaming route records first draft and readiness. Browser events measure first received draft and readiness from the explicit action, including staging; the display animation runs independently. Browser/server durations are separate clock domains. Existing bounded timing helpers are reused with a separate event namespace. No CV text, raw chunks, filenames, prompts or credentials are logged.

Before claiming the latency target, run representative owner-authorized live interactions and record input sizes, sample count, successful/failed primary and fallback cases, first-text and ready durations, and p50/p95. Check deployed proxy buffering separately. Synthetic tests prove boundaries/recovery, not provider speed or generated-writing quality.

## Compatibility: point editor

The following describes the retained point editor and its shared scoring foundations. New whole-entry sessions use the flow above.

## User flow

- Select a point to edit it directly or choose **Improve this point**. One proposed replacement appears in that card. The original is behind **Compare with original**. **Use this** splices only the selected text range; surrounding whitespace and list markers stay intact. **Try again** is an explicit new request.
- **Add a point** accepts a finished point or rough notes. **Shape this point** confirms the submitted notes as reusable evidence before generating wording. Optional discovery helps recall another achievement.
- **Help me add more detail** asks up to three short free-text questions, one visible at a time. Answers can be skipped or the round finished early. Going back resumes an unfinished round without another generation. Tools are suggested only as unselected actions drawn from the existing technical-skills list. The user confirms their answer before it becomes evidence.
- Skipping every discovery question with no notes creates no duplicate point. Saved answers themselves do not change CV text or its score.
- Historical **Review skills** receipts remain readable, but their supporting quotes and reference metadata are retired. Skill choices retain only the IDs needed for deduplication and exclusions.
- **Updated / Undo last update** restores only the last applied experience text, and only while it exactly matches the applied result. Original imported facts remain available separately.

The modal uses native dialog isolation, keyboard containment, focus restoration, an independently scrolling body, and a persistent footer. The writing workspace expands to 1220px within viewport margins. On desktop, a persistent right-hand panel shows the current writing-quality score, one actionable priority point and a separate coverage checklist for four areas: personal contribution, methods/tools, scope/audience, and purpose/outcome. Each area explains what is missing, what could be clearer, or what is well explained, with optional supporting wording. The next unusable or weak point is highlighted. Unassessed or stale wording receives neutral guidance rather than unsupported claims of missing information. At widths of 1000px or less, this panel becomes a collapsible summary above the writing area. Writing and guidance scroll independently on desktop; the footer stays visible. Opening the modal prioritizes its queued assessment without duplicating it; expanding guidance never starts an AI request.

## Writing assessment and diagnostics

The active policy is `experience-score/5`, persisted as `experience-quality/3`. The assessment-only system prompt is [experience-assessment-prompt.ts](../../packages/contracts/src/intelligence/experience-assessment-prompt.ts); [experience-assessment.ts](../../apps/api/src/intelligence/experience-assessment.ts) defines the wire schema and normalization. The approved six examples calibrate contribution, clarity, specificity and the sufficiency test. The model assesses applied CV wording, never competence, career truth, hiring probability or an unspecified vacancy.

The server computes point quality as `40 × contribution + 30 × clarity + 30 × specificity`, with missing/partial/specific worth 0/.5/1. Experience quality is the rounded mean across all points. Unusable entries earn zero. Repeated points after the first earn zero and reference the earlier point; related responsibilities are not automatically duplicates. Coverage and qualitative observations do not add points. A concise responsibility can receive 100 without software, numbers or a measured outcome. The market-entry anchor receives 65 for partial/specific/partial.

The model input contains `locale` (feedback language), `documentLocale` (CV language), `role`, `scope`, and `points: [{id,text}]`. Text appears once; original offsets and source mappings stay on the server. The scorer receives no company, dates, other jobs, private coaching answers or target vacancy. New scoring, questions, skill suggestions and wording use `contentLanguage(draft)`, resolved from `documentLocale` then legacy `language`. Interface controls use the independent UI language. UI language switches do not invalidate questions or answers. Existing operation receipts retain their original locale for recovery. Imports may provide optional `detectedLanguage`; historical payloads remain supported. The Profile content-language selector corrects legacy drafts without translating their existing text, and explicit job output language takes precedence for job copies.

Every point returns grades, meaningfulness, an issue, `duplicateOf`, and nullable `strength`, `improvement` and `suggestedQuestion`. Diagnostics are bounded to 240 characters each. The UI displays one selected point's advice and question, recognizes sufficient points, and never creates an issue from a numeric threshold alone. The profile and modal use the same current assessment and priority policy: unusable text, repetition, contribution, clarity, then useful context. A model-selected priority is honored within the appropriate priority tier.

The four coverage dimensions remain contribution, methods, scope and outcome, with source point IDs resolved to original wording. Not stated coverage is neutral and creates no automatic demand for more detail. A complete entry can additionally return qualitative distinctiveness, professional value and coherence observations, plus a priority point. These observations cite source point IDs and contain no extra numerical score. A single point cannot establish distinctiveness.

Assessment remains one request for a normal experience, bounded to 12 units / 7,800 characters. Long points split into at most 6,000-character units and merge conservatively once. Chunked or split entries have `scope: partial` and no whole-experience review. A fragmented point's diagnostics are suppressed rather than joined into an unsupported statement. Exact repeats are detected across chunks. The output allowance scales from `1000 + 250 × unit count`, capped at 4,000 tokens. The existing 25-second deadline, provider routes, attempt accounting, and bounded fallback remain in place; no automatic paid repair is introduced.

JSON structure, complete point coverage, allowed IDs, grades, evidence references, duplicate ordering and stored score arithmetic are validated. Invalid grades or source bindings fail assessment. Invalid diagnostic prose or holistic references fall back to generic guidance without discarding otherwise valid grades or generating another request. Structured output is not proof that a semantic judgment is correct or in the requested language; live model evaluation remains separate.

Help me add more detail reuses the current saved diagnostic question without inference. An existing answer to that question is reused; confirmed answers stay independent of applied CV text. Adaptive questions and rewriting remain explicit operations. They use current diagnoses and bounded confirmed evidence; proposed CV wording uses `documentLocale`, while explanations and questions use the feedback `locale`. Only Use this changes the CV. Legacy shared callers and failed assessments retain manual editing and recovery.

## Persistence and request handling

`BaseDraft.experienceEnrichment[roleId]` is optional, versioned, bounded metadata validated by the editor codec. It stores the open editor, current coaching round and answer references, foreground operation identity, independent `scorePending`/`scoreError` state, proposed point, skill decisions, score, and guarded Undo state. Score failures never lock manual editing. Confirmed answers and their sources use the existing evidence archive. Editing an answer preserves its previous citation for already applied wording while superseding it in future assistant context.

`POST /v1/intelligence/experience` accepts the owned saved snapshot/revision, target role, operation UUID, and an `experience` request with intent `point`, `questions`, `skills`, or `score`. SHA-256 binds visible wording, accepted evidence, role labels and document locale. Point offsets and exact source text are resolved against that snapshot before reservation or inference. Late responses are checked again against the latest role identity; unrelated edits are preserved.

A foreground user action or a queued background assessment first saves its operation identity through ordinary autosave. Only after acknowledgement does the component dispatch. On refresh it reads `/v1/intelligence/operations/{id}`; it never replaces an uncertain operation with a new generation. Interrupted work has at most six automatic read-only recovery checks, with manual checks available afterward. Returning to the foreground modal rechecks its existing receipt. A missing scoring receipt resumes dispatch using the same UUID after the current draft is saved; missing foreground receipts offer explicit continuation, and uncertain receipts expose a read-only progress check. A failed save exposes the existing save retry control.

All provider stages use the configured structured runner, owned snapshot reservations, durable attempt accounting, output validation and fallback. Point generation has one accounted stage: wording. Applied-text scoring is a separate operation. The new endpoint verifies the session before paid dispatch without waiting for another advisory score request to finish. Account and CSRF fences remain in place. Its execution has a 25-second deadline independent of the browser connection and is registered with Worker `waitUntil`, allowing a disconnected browser to recover the completed receipt. Receipt persistence retries never repeat inference; a lost acknowledgement reads the saved result first. If receipt persistence is temporarily unavailable, the validated result is still delivered for ordinary draft saving while persistence is retried in the background. Role-wide skills and score requests use bounded chunks; point context stays within 24 facts / 8K factual text. Long individual facts are split for provider input, retaining their original citation identity. Large selected paragraphs require shortening before generation.

## Automatic profile assessment

### Questions ready before selection

**Improve your experience through questions** first resumes a compatible unfinished round, including saved whole-role questions. Otherwise it selects actionable low-scoring guidance and uses the diagnostic question or prepared cache. This avoids a second generation request and the save/request wait; answer hints and optional examples remain beside the answer field. Reopening the same current round preserves its draft answer. Round reuse requires matching evidence fingerprint, content language and exact point. Confirming an answer advances that round’s evidence fingerprint, preserving the remaining questions and any unfinished answer when returning to the point.

When the current experience score is below 80, points below 80 without a suggested question queue up to three preparations per role/input, one background operation at a time. Preparation starts for a completed role independently of other roles still scoring. It waits for autosave and pauses new preparations during foreground requests. Existing diagnostic questions cost no additional call. Preparations have their own bounded metadata and operation receipts, separate from foreground work and scoring; advisory saves merge only their own fields into the latest editor state. Clicking an in-flight preparation waits for that same operation, with Back available. Unknown outcomes retain their IDs for read-only recovery; they are not automatically regenerated. If recovery reports an unavailable result, an explicit retry retires that preparation and creates a fresh operation. Text/evidence or content-language changes prevent reuse of old results. No questions or examples are treated as confirmed user evidence.

A single profile-level coordinator assesses missing or changed job experiences sequentially, including existing profiles on their next visit. It waits 1.5 seconds after semantic inputs settle and for successful autosave before dispatch. Unsaved edits, failed saves, pending imports, and explicit foreground writing actions pause new background work. Closing the profile pauses undispatched work; the next visit resumes it. The existing operation receipts retain dispatched work across disconnects. No separate worker or database migration is required.

The shared `experience-policy.ts` contains the assessment version, weights, thresholds, and settling interval. New assessments record their policy version and feedback locale; historical weight definitions remain registered so a future policy change cannot make saved profiles undecodable. Cached input identity includes policy version, applied wording, the role label actually sent to assessment, document language and the request’s feedback language. Names, company names, private coaching answers and assessment metadata do not invalidate a score. Interface language changes alone do not launch bulk inference. Valid current-policy writing-quality results are reused and annotated with their input identity. The previous `experience-score/3` and `/4` assessments remain decodable but are stale under `/5`, including results without an explicit policy version; the existing queue reassesses them on the next profile visit. Policy version changes invalidate assessments lazily on profile visits, never through a bulk task.

A content-derived operation UUID includes the profile ID, stable role ID, assessment identity, and explicit retry number. The API validates that identity against an owned saved snapshot, replays results across autosave revisions, and uses the existing atomic operation claim to deduplicate concurrent tabs. Scoring uses a separate reservation policy from rewriting. Terminal failures remain recorded and do not automatically retry on visits. The guided view exposes assessment retry, progress checks and recalculation. Explicit new attempts require a settled server receipt (`ready`, `failed` or terminal `unknown`); a processing receipt cannot be replaced. Unknown work first receives bounded read-only recovery. Recalculation preserves the previous score until a current replacement succeeds and stores the attempt in backward-compatible assessment metadata.

Profile cards show Writing quality, one assessment-backed improvement hint, and reviewing/updating/unavailable status. Strong experiences receive positive feedback rather than invented weaknesses. The modal reads the same result. Changed wording retains a labelled previous score while outdated point guidance is suppressed. Assessment updates merge only advisory fields into the latest draft, preserving concurrent edits, coaching state, and user Undo history. Late results for changed text, deleted roles, replaced profiles, or retired sessions are ignored.

## Job copies and validation

`selfContainedJobDraft` and `app.freeze_job_document` remove enrichment metadata along with the private answer archive. Accepted wording and user-selected skills remain in the CV. The additive migration preserves the existing SQL function's privileges and security properties. Development migrations: `20261101004420` and `20261101110459`. The latter makes receipt acknowledgement idempotent and prevents success from being downgraded. It retires only proven legacy score failures. A stale receipt with a known completed point but no retained result becomes retryable through the read projection; genuinely unknown provider outcomes remain fenced. Both paths preserve usage accounting and never start inference.

Coverage includes contract roundtrips, exact-range preservation, stale scope rejection, provider-stage reservations and parent replay, numerical grounding, quoted score evidence, score ceilings and decreases, optional coaching, refresh recovery, skill choices and deduplication, guarded Undo, and SQL job-copy stripping.
