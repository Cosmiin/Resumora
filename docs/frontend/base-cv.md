# Local Base CV editor · J05–J08

The React/Vite app implements the Base CV journey with the supplied Resumora design. The latest owner request replaces section modals and repeated confirmations with inline editing, compact fields, chip inputs and session autosave. Auth, Supabase, PDF/DOCX extraction, AI, job tailoring and export remain unconnected. No account is required for local review; use synthetic data.

## Run and review

Use the pinned Node/npm versions from `.nvmrc` and `package.json`, then run from the repository root:

```sh
npm ci --ignore-scripts
npm run dev:web
```

Manually open **http://127.0.0.1:5173/** in the owner's `cosmin@emedi.ro` Chrome profile. Ctrl+C stops this server. `npm run dev` also starts the existing Worker; Base CV editing needs only the web app. Do not run HTTP smoke while the dev pair occupies its ports.

1. Create a Base CV → enter manually. The first inline section focuses the first empty field. Enter first name, last name, professional title, email, phone, city and LinkedIn using typing and Tab. All seven fields are required for a completed checkpoint. The second title, website, other profiles and full address remain optional. Optional contact buttons add and focus a field in one click.
2. Expand a section in place. Enter in a single-line field advances to the next field; multiline inputs retain Enter. Skills use Enter/comma/delimited paste, preserve multiword names, edit at click and remove with × or empty-input Backspace. Drag a handle or use Alt+↑/↓ on the item to reorder. Field visibility uses the label's eye or Alt+V in the field. Structure controls are in a collapsed panel.
3. Add experience/education: the new entry's first field receives focus. Dates accept `LL/AAAA` (`MM/YYYY` in EN), six digits or a year only; an absent month remains unknown. The optional calendar icon or Alt+↓ opens a visual year input and twelve month choices, with no day grid/input. Choose a month to apply and close; Year only and Unknown date retain those precision levels. Opening/dismissing the picker assigns no date, and the typed path needs no extra Tab, click or confirmation. Ongoing hides the end-date control without deleting its prior value. Edit all contributions in one rich-text field with bold, italic and bulleted/numbered lists. Pasted content is plain text; saved formatting is restricted to safe text/list markup.
4. At least one language is required for completion. Select a self-assessed CEFR A1–C2 level with the level meaning in the option, or Native separately. Native implies no CEFR level or certification. UI and CV languages remain independent; changing CV language changes headings/date formatting, not the user's text.
5. Typed content appears immediately in the **draft** preview. Click a preview block to reveal and focus its field. No mobile preview toggle is introduced. Source/status details are hidden in a section information disclosure; imported unconfirmed facts keep their status. Reference/generated prose is never silently accepted. Direct manual edits are recorded as user-authored facts with prior source lineage retained; the app adds no repeated fact/section confirmation or invented legal attestation.
6. Improve → select an experience, certification, project, volunteering or custom entry. A compact entry summary and one manual question appear beside the preview. Ctrl/Cmd+Enter saves the full question and exact answer as independent career context and advances without changing CV text; Ctrl/Cmd+Shift+K records Unknown, Ctrl/Cmd+Shift+J skips. The visible context answer can be edited in its preview. Optional Add/Update/Remove in CV actions affect only an explicitly linked CV copy; later context saves never overwrite independently edited CV wording or erase Q&A. Responsibilities, ownership, technical skills, scope/scale, achievements, impact and complexity are covered. Job relevance stays unavailable without reviewed job context. There is no AI analysis or fabricated metric.
7. Edits coalesce after 650ms of inactivity into immutable in-memory snapshots, including incomplete drafts. The sticky bar shows save state and one primary **Save now** action (Ctrl/Cmd+S). Explicit save checks completion/syntax and preserves input; validation failures open the Base CV editor and focus the first invalid field. No acknowledgment checkbox is required, and successful save stays on the current screen. A failed/conflicting save retains the draft; ordinary navigation is available. Undo survives autosave.
8. Home → reopen the latest session draft. History → inspect/restore an earlier snapshot. Restore creates a new version and retains old snapshots. A destructive draft replacement/restore keeps its explicit cancellation dialog; this is separate from ordinary section editing. Newer edits made while an adapter operation is pending are retained.
9. Existing-document selection has a styled native picker and drop target. It validates only name/size metadata, rejects empty/unsupported/multiple selections and offers manual continuation. It never reads, uploads, parses or stores file bytes.

**Persistence boundary:** the adapter holds one Base document and cloned snapshots in this page's memory. Reloading/closing clears all drafts and versions, including those described as saved. A new adapter instance is empty. No browser storage, cookies, network writes, login or cloud sync is implied. The reload warning depends on browser support. An autosaved draft can remain incomplete or contain unreviewed imported facts; saving it is not attesting those facts or making it export-ready.

## Code and replacement boundary

- `base/model.ts` is an application projection, not a canonical serializer/API payload. `user_authored` distinguishes direct entry from imported `extracted_unconfirmed` facts. `base/editing.ts` replaces edited facts while retaining stable field handles and source lineage. Name parts are explicit; arbitrary imported names are never automatically split. Mara parts are mapped explicitly from the synthetic fixture.
- `base/adapter.ts` exposes asynchronous load/history/save/restore, with optional autosave versus completion-checkpoint mode. It clones across boundaries, checks revisions, replays identical requests, rejects changed replays, avoids no-op versions and restores as new checkpoints. Callers serialize writes and guard against late replies replacing newer drafts. No hosted concurrency/retention guarantee is claimed.
- Synthetic claim/evidence labels remain local fixture references, never database UUID foreign keys. A real adapter must explicitly validate/translate the canonical graph, server-derived identity/ownership, provenance, revisions and request identity. No backend/schema/auth/provider contract was changed.
- Source facts, pending reference prose, user-authored wording and presentation remain separate. Contribution formatting is presentation linked through stable contribution associations; Add/Update/Remove and preview edits modify only the affected associated content while retaining unrelated bold/italic/list markup. Preview formatting is sanitized again on rendering. Enrichment retains exact answer text/source/target references and checks stale destinations.
- `base/dates.ts` retains the existing month-index interval union: overlaps count once, partial dates produce bounds, invalid/unknown years and unreviewed intervals are excluded and reported. No days, January starts or exact tenure are invented.
- Native accessible controls, locally served licensed fonts, Lucide icons and the supplied pine/sage/marigold tokens are retained. Original reference ZIP/assets are unchanged. Reordering has drag and keyboard paths; deletion/visibility remain discoverable on focus/touch.

## Verification and limits

The [local development checks](../setup/local-development.md#checks) own validation and formatting commands. They do not launch Chrome, Playwright or another browser.

The behavior suite exercises identity Tab/focus, contact/visibility actions, chip editing/cancel/paste/delete/reorder, entry/date behavior, optional month/year picker selection/dismissal and precision, preview navigation, languages, safe contributions, manual enrichment/skip/unknown, incomplete autosave, explicit validation, failure/conflicts/replay/no-op, late saves, Undo, reopen and immutable restore. The [action evidence](action-budgets.md) records separately captured production-bundle traces and their revision limits. These checks do not establish native geometry, pointer drag, file-picker behavior, real Tab focus, screen-reader output or touch behavior.

Native review targets are **1366×768 desktop** and **390×844 mobile**, plus 200% zoom. The mandated Chrome profile has not been positively bound for agent control, so no native screenshot, layout pass or measured native scroll count is claimed. The [action table](action-budgets.md) distinguishes observed DOM events from layout estimates and remaining manual checks. Narrow/zoomed screens and long entries may scroll vertically to retain readable controls; the save bar stays reachable. No clipping, tiny text or hidden mobile preview switch is used to manufacture a no-scroll result.
