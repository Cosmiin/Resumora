# Local Base CV editor · J05–J08

The React/Vite app implements the Base CV journey with the supplied Resumora design. The latest owner request replaces section modals and repeated confirmations with inline editing, compact fields, chip inputs and session autosave. The application entrypoint now requires Supabase authentication and uses the user-scoped Worker persistence gateway. PDF/DOCX extraction, job tailoring and export remain deferred; [connected vacancies and scoped wording](../setup/connected-jobs-ai.md) owns the added job and default-OFF AI behavior. Use authorized synthetic accounts/data for controlled review.

## Run and review

Use the pinned Node/npm versions from `.nvmrc` and `package.json`, then run from the repository root:

```sh
npm ci --ignore-scripts
npm run dev
```

Configure the private Worker settings described in [authentication setup](../setup/authentication.md), then follow its [browser verification requirements](../setup/authentication.md#external-setup-dependencies) before opening **http://127.0.0.1:5173/**. Sign in with an authorized account to reach the editor. Ctrl+C stops the local frontend/Worker pair; the composed app requires both. Do not run HTTP smoke while the dev pair occupies its ports.

1. Create a Base CV → enter manually. The first inline section focuses the first empty field. Enter first name, last name, professional title, email, phone, city and LinkedIn using typing and Tab. All seven fields are required for a completed checkpoint. The second title, website, other profiles and full address remain optional. Optional contact buttons add and focus a field in one click.
2. Expand a section in place. Enter in a single-line field advances to the next field; multiline inputs retain Enter. Skills use Enter/comma/delimited paste, preserve multiword names, edit at click and remove with × or empty-input Backspace. Drag a handle or use Alt+↑/↓ on the item to reorder. Field visibility uses the label's eye or Alt+V in the field. Structure controls are in a collapsed panel.
3. Add experience/education: the new entry's first field receives focus. Dates accept `LL/AAAA` (`MM/YYYY` in EN), six digits or a year only; an absent month remains unknown. The optional calendar icon or Alt+↓ opens a visual year input and twelve month choices, with no day grid/input. Choose a month to apply and close; Year only and Unknown date retain those precision levels. Opening/dismissing the picker assigns no date, and the typed path needs no extra Tab, click or confirmation. Ongoing hides the end-date control without deleting its prior value. Edit all contributions in one rich-text field with bold, italic and bulleted/numbered lists. Pasted content is plain text; saved formatting is restricted to safe text/list markup.
4. At least one language is required for completion. Select a self-assessed CEFR A1–C2 level with the level meaning in the option, or Native separately. Native implies no CEFR level or certification. UI and CV languages remain independent; changing CV language changes headings/date formatting, not the user's text.
5. Typed content appears immediately in the **draft** preview. Click a preview block to reveal and focus its field. No mobile preview toggle is introduced. Source/status details are hidden in a section information disclosure; imported unconfirmed facts keep their status. Reference/generated prose is never silently accepted. Direct manual edits are recorded as user-authored facts with prior source lineage retained; the app adds no repeated fact/section confirmation or invented legal attestation.
6. Improve → select an experience, certification, project, volunteering or custom entry. A compact entry summary and one manual question appear beside the preview. Ctrl/Cmd+Enter saves the full question and exact answer as independent career context and advances without changing CV text; Ctrl/Cmd+Shift+K records Unknown, Ctrl/Cmd+Shift+J skips. The visible context answer can be edited in its preview. Optional Add/Update/Remove in CV actions affect only an explicitly linked CV copy; later context saves never overwrite independently edited CV wording or erase Q&A. Responsibilities, ownership, technical skills, scope/scale, achievements, impact and complexity are covered. Job relevance stays unavailable without reviewed job context. Optional wording suggestions follow the [connected setup guide](../setup/connected-jobs-ai.md#enhancement-behavior); no metric is fabricated.
7. Edits coalesce after 650ms of inactivity into immutable snapshots, including incomplete drafts. The sticky bar shows save state and one primary **Save now** action (Ctrl/Cmd+S). Explicit save checks completion/syntax and preserves input; validation failures open the Base CV editor and focus the first invalid field. No acknowledgment checkbox is required, and successful save stays on the current screen. A failed/conflicting save retains the draft; ordinary navigation is available. Undo survives autosave. With the HTTP adapter described below, **Retry** replays the exact unresolved save or restore. Network/server failures retain that request; a later authentication/access denial does not resolve the original uncertain outcome. An authoritative revision conflict releases the request and offers **History** before explicit reopen, retaining local edits. If replay has expired, **Check saved state** reconciles the saved head while retaining newer edits. A definite input rejection releases the failed request: correcting the input resumes autosave, including corrections made while the rejected request was pending. An unchanged rejected draft keeps its error without repeated automatic submissions.
8. Home → reopen the latest saved draft. History → inspect/restore an earlier snapshot. **Inspect** focuses and scrolls to the selected version's heading, including when inspecting the same version again. Its CV preview appears above the version list on narrow screens and top-aligned beside it on wide screens. **Close inspection** dismisses the preview; inspection retains all versions and their contents. Restore creates a new version and retains old snapshots. A destructive draft replacement/restore keeps its explicit cancellation dialog; this is separate from ordinary section editing. Newer edits made while an adapter operation is pending are retained. **Retry history** repeats only the history read and retains the current draft. If the initial load fails, manual editing and Undo remain available, but save/restore wait for a successful baseline read. **Retry** repeats that read without replacing local edits; a different saved draft then requires explicit conflict recovery, while a successful empty result allows the first save.
9. Existing-document selection has a styled native picker and drop target. It validates only name/size metadata, rejects empty/unsupported/multiple selections and offers manual continuation. It never reads, uploads, parses or stores file bytes.

**Persistence boundary:** the composed entrypoint supplies a per-account/session HTTP adapter backed by the authenticated Worker gateway, with no memory fallback. Successfully saved snapshots can be loaded after reopening and signing in to the same account; unsaved edits remain in the current page. The isolated editor component's default memory adapter remains available for unit tests and holds one Base document and cloned snapshots in page memory. Only with that memory adapter does reloading/closing clear all drafts and versions, including those described as saved; a new memory adapter instance is empty. That isolated default makes no browser-storage or network writes. The reload warning depends on browser support. An autosaved draft can remain incomplete or contain unreviewed imported facts; saving it is not attesting those facts or making it export-ready.

## Persistence component handoff

This change delivers the independently deliverable Persistence component for review: `HttpBaseCvAdapter` in `apps/web/src/base/http-adapter.ts`, `cvRoute(request, gateway)` in `apps/api/src/cv/routes.ts`, and shared editor modules under `@resumora/contracts/editor/*`. The composed frontend now supplies `HttpBaseCvAdapter`, and the Worker entrypoint mounts these routes after Auth verification and write Origin/CSRF checks. Memory-backed drafts or saved heads retain unload protection; a durable adapter warns for unsaved edits, unresolved writes that may differ from the current draft, and unresolved conflicts.

The [session and request contract](../setup/authentication.md#session-and-request-contract) owns authentication composition, temporary verification failures, account isolation and transport retirement. The [database runbook](../database/runbook.md) owns development migration checks and apply prerequisites.

The agreed connected milestone remains required. Final acceptance is pending on a compatible composed head using the existing cloud development Supabase project: signup/signin/signout/password reset; incomplete CV and exact enrichment-answer recovery after close/reopen; immutable history and restore; stale/replayed request handling; and isolation between accounts. Module tests use synthetic doubles and do not prove hosted save/recovery or account privacy. Hosted migration approval remains separate; component delivery does not complete that milestone.

## Code and replacement boundary

- `packages/contracts/src/editor/model.ts` owns the shared editor projection; `apps/web/src/base/model.ts` re-exports it. It is distinct from the canonical CV graph; `packages/contracts/src/editor/transport.ts` owns its wire envelope. `user_authored` distinguishes direct entry from imported `extracted_unconfirmed` facts. `base/editing.ts` replaces edited facts while retaining stable field handles and source lineage. Name parts are explicit; arbitrary imported names are never automatically split. Mara parts are mapped explicitly from the synthetic fixture.
- `base/adapter.ts` exposes asynchronous load/history/save/restore, with optional autosave versus completion-checkpoint mode. Its memory implementation clones across boundaries, checks revisions, replays identical requests, rejects changed replays, avoids no-op versions and restores as new checkpoints. The HTTP implementation delegates persistence to the gateway through `cvRoute`; the shared `editor/validation` module owns checkpoint validation. Callers serialize writes and guard against late replies replacing newer drafts. No hosted concurrency/retention guarantee is claimed.
- Synthetic claim/evidence labels remain local fixture references, never database UUID foreign keys. The shared editor transport defines draft/context roundtrips; the separate [database gateway contract](../database/gateway.md#unconfirmed-editor-state) owns unconfirmed snapshot persistence and its identity/revision/request boundary. Composition uses the shared editor projection and that gateway contract; saving pending input does not publish a confirmed canonical graph. See the [component handoff](#persistence-component-handoff) for composition and verification status.
- Source facts, pending reference prose, user-authored wording and presentation remain separate. Contribution formatting is presentation linked through stable contribution associations; Add/Update/Remove and preview edits modify only the affected associated content while retaining unrelated bold/italic/list markup. Preview formatting is sanitized again on rendering. Enrichment retains exact answer text/source/target references and checks stale destinations.
- `packages/contracts/src/editor/dates.ts`, re-exported by `apps/web/src/base/dates.ts`, retains the existing month-index interval union: overlaps count once, partial dates produce bounds, and intervals with missing/invalid years, invalid months, impossible chronology or future starts are excluded and reported. `DocumentPreview.tsx` filters unreviewed intervals before calculation and includes them in the unknown count. No days, January starts or exact tenure are invented.
- Native accessible controls, locally served licensed fonts, Lucide icons and the supplied pine/sage/marigold tokens are retained. Original reference ZIP/assets are unchanged. Reordering has drag and keyboard paths; deletion/visibility remain discoverable on focus/touch.

## Verification and limits

The [local development checks](../setup/local-development.md#checks) own validation and formatting commands. They do not launch Chrome, Playwright or another browser.

The behavior suite exercises identity Tab/focus, contact/visibility actions, chip editing/cancel/paste/delete/reorder, entry/date behavior, optional month/year picker selection/dismissal and precision, preview navigation, languages, safe contributions, manual enrichment/skip/unknown, incomplete autosave, explicit validation, failure/conflicts/replay/no-op, late saves, Undo, reopen and immutable restore. Injected HTTP/gateway checks cover request-size rejection, uncertain outcomes and denied retries, initial-baseline recovery, account/adapter changes and history pagination. The [action evidence](action-budgets.md) records separately captured production-bundle traces and their revision limits. These checks do not establish native geometry, pointer drag, file-picker behavior, real Tab focus, screen-reader output or touch behavior.

The Test phase used headless Playwright Chromium with fresh contexts after the Chrome bridge failed. That fallback violated the explicit `cosmin@emedi.ro`-only/no-fallback policy; no waiver was granted. The original audit artifacts remain unapproved-method evidence, and those screenshots and scenarios are excluded from approved native/profile acceptance. Independent focused Vitest/Node component evidence remains valid.

Native owner-profile review and real hosted Supabase/Auth/account-isolation acceptance remain outstanding. Eventual PR validation reporting must retain this disclosure and distinguish component evidence from final connected-milestone acceptance.

Native review targets are **1366×768 desktop** and **390×844 mobile**, plus 200% zoom. The mandated Chrome profile has not been positively bound for agent control, so no native screenshot, layout pass or measured native scroll count is claimed. The [action table](action-budgets.md) distinguishes observed DOM events from layout estimates and remaining manual checks. Narrow/zoomed screens and long entries may scroll vertically to retain readable controls; the save bar stays reachable. No clipping, tiny text or hidden mobile preview switch is used to manufacture a no-scroll result.
