# CV import and career enrichment

This implementation connects authenticated document intake, unconfirmed review, exact saved Q&A and selected-role semantic wording proposals to the existing Worker/Supabase/editor persistence and AI attempt ledger. Paid execution remains OFF. No hosted migration, bucket, secret, provider request or real CV was used to validate it. The earlier quote-composition endpoint remains available; whole-role rewriting uses the separate structured operation below.

## Customer journey and saved truth

1. Choose PDF, DOCX or DOC, then explicitly upload/analyse. All source files are limited to **10,000,000 bytes**. PDF has an exact maximum of **10 pages** counted from its parsed page tree, including scanned/mixed documents. Word uses bounded text/container processing and native provider reading; original Word pagination is unknown, and a ten-page Word guarantee is intentionally absent.
2. The authenticated Worker verifies type/content and size, creates an owned private source/import record, and performs deterministic bounded preflight. It never executes document scripts, Office, local OCR or external document resources. A small configured AI model classifies CV / not-CV / uncertain. Only CV admission triggers the stronger extraction model. Both stages are metered separately. Non-CV/uncertain results stop; there is no automatic escalation or expensive rerun.
3. Extraction creates candidates with field path, source quotation, PDF page (Word `null`), confidence and warnings. These are **extracted_unconfirmed**, including high-confidence output. Provider-native transcription is not an independently verified quotation: the review warns about visual/Word evidence. Missing names, dates and figures stay missing; a full name is never automatically split into first/last name. Opening a recovered review starts a new draft rather than merging over newer edits.
4. Ready extraction automatically opens Base CV review. Review one section at a time: identity/contact, original summary, individual roles, education and optional categories. High-confidence values without a specific warning are accepted automatically and omitted from manual review; their facts remain extracted with an explicit `acceptance: "automatic"` marker, never falsely user-confirmed. Review, enrichment/rewrites, duration and job-editor eligibility share that persisted acceptance rule: eligible editor facts are user-authored, user-confirmed, or extracted with the explicit automatic marker. Historical unconfirmed facts without the marker remain pending; confidence alone never promotes them. Uncertain or specifically warned fields enter staged review; only the two exact stock extraction notices are exempted. Only candidates with a current stored fact enter review, including inactive end dates and facts linked through edit lineage. Removing a fact or entry keeps its source candidates and history without reopening review or recording a new confirmation for absent fields; present facts without automatic acceptance or a recorded confirmation remain pending, including after restoration. Editing preserves original candidates/quotes and field lineage. **Confirm and continue** approves the visible section and records its selection through the existing atomic review-save path, even while other sections are incomplete. Saves with recorded import confirmations use `saveReviewedImport` in both autosave and checkpoint mode; normal completion validation still applies to a later full checkpoint. Original summaries use one sourced Summary editor/output in place of the empty core summary; they require no invented entry title. Custom category headings live in a sourced section `heading` fact and render once. Entry reorder/deletion cannot rename the section; the original content entry has the stable section ID and needs no duplicate title. Certifications use the existing certification category; other source categories use custom sections.
5. In enrichment, select a role and click **Îmbunătățește / Improve**. This requests one batch of up to three questions, framed by the eligible role title or stable category heading, eligible role description/bullets and relevant prior answers. Each question addresses a concrete gap, with up to six distinct role-relevant possibilities or free text when choices would be speculative. The title frames questions only; it is not evidence of accomplishments. No answer is preselected. Single/multiple/zero choices and optional text/text-only are supported. Click a selected option again to deselect it; there is no separate clear button. Save-and-next, skip and unknown are deterministic; no inference runs per option or keystroke. Exact question, options, selections, text and status persist in editor snapshots independently of CV contributions. If question generation fails, **Continue with manual questions** keeps manual entry available. **Edit answer** reopens saved answers, including manual answers and answers whose question plan is no longer retained. **Add to CV** is optional and explicit; removing that copy retains Q&A.
6. Completing the question batch (saving, skipping or choosing unknown on its last question) automatically queues one whole-experience rewrite after the existing autosave coordinator confirms the current draft is saved. Uncertain saves wait for the existing retry/reconciliation flow; changing eligible evidence or undoing batch completion before dispatch cancels the queued request. After manual fallback, save an answer and use **Propose experience rewrite** once autosave completes. The rewrite sends only the selected role's eligible context and saved confirmed Q&A; saved questions explain answers but are not factual evidence. It returns a complete cited semantic rewrite saved as a pending before/after review. Generation failure retains answers and offers a deliberate retry; returning to an already completed batch does not silently generate again. Edit/Accept/Reject are explicit. Accept changes the selected presentation wording overlay; original facts and Q&A survive. Source changes invalidate accepted wording. Source IDs and numeric-token checks reject some unsupported output, but do not prove semantic entailment: inspect meaning before accepting. Question/choice quality and rewrite tone now have role-specific prompt guidance, but live provider quality is unverified. Job-mode AI enrichment remains unavailable: the current intelligence endpoints use owned Base snapshots, so the existing job editor guard prevents an unsafe Base write.

This is editor-draft persistence, not publication of confirmed canonical career claims or a canonical Base CV version. Automatic acceptance is an editor decision, not canonical user confirmation. The source manifest reuses the existing unpublished personal-profile shell/source/span boundaries. No ATS semantic score, readability score, vacancy tailoring, photo processing or export is added by this feature.

## Runtime and input bounds

PDF preflight uses the pinned maintained `@cantoo/pdf-lib` fork inside the Worker. It traverses actual page-tree children rather than trusting `/Count`, rejects encrypted/malformed documents and bounded dangerous object structures, and uses depth/node/object limits. All accepted PDF pages are passed to the configured native vision/file route. There is no native OCR subprocess and no hosted Workers Free CPU/memory guarantee. Network-denied workerd tests cover mixed/scanned structure, forged counts, 11 pages, nested JavaScript, malformed input and near-10MB sources; pathological compressed structures and real document quality still need activation evaluation.

DOCX uses `fflate` with ZIP checks, bounded streamed expansion, no encrypted/macro/DTD input, 10MB total expanded bytes, 500KB per XML entry and 1MB aggregate XML. Extracted relevant text is limited to 40,000 characters. Legacy DOC uses `cfb` to inspect OLE/WordDocument, reject encryption/macros/embedded objects and conservatively limit WordDocument bytes to 40,000 and metadata to 160,000. Formatting-heavy legacy files may be rejected even when visually short. `cfb` is a small older dependency (1.2.2); dependency maintenance remains an explicit operational risk. No Office converter/service is installed. Provider-native Word reading is text based; Word image OCR is not promised.

Structured extraction allows at most 250 candidates and 40,000 combined candidate-value/quote characters. Partial dates are year or month/year, with uncertain dates left pending. Career evidence is bounded to 24 facts, 2,000 characters per fact and 8,000 total; these bounds cover the fact array, excluding supplemental question text and the role-title hint. Confirmed answers retain their own identities even when also copied into CV fields. Whole-experience wording stays active only while the complete accepted input matches, including uncited facts and confirmed answers. It omits identity/contact/employer/raw document fields (questions additionally receive an eligible role-title hint), but role free text can still contain personal information; minimization is not anonymization.

## Provider seam and operation contracts

Reuse the existing session/CSRF and durable operation/attempt store. Raw binary is allowed only for the exact import POST; other write routes keep JSON protection. No client tenant/owner ID, arbitrary provider URL, model or schema is accepted.

| Trigger | Operation/version | Input/output contract | Route |
| --- | --- | --- | --- |
| Upload/analyse, stage 1 | `cv.admit.v1-provisional` | trusted file/page bounds → CV/not-CV/uncertain + reason/evidence pages | PDF: OpenRouter native-file primary, one direct OpenAI fallback; Word: direct OpenAI Responses |
| CV admitted, stage 2 | `cv.extract.v1-provisional` | same bounded source → unconfirmed candidates + evidence/warnings | Same format-specific route, stronger configured model |
| Improve | `career.questions.v2-role-guided` | owned saved snapshot/role/prior Q&A → role-guided question plan | Existing OpenRouter primary/direct OpenAI fallback |
| Saved batch completion or deliberate rewrite request | `career.role-rewrite.v2-saved-context` | owned saved snapshot/role/evidence/Q&A → cited pending full-role wording | Existing OpenRouter primary/direct OpenAI fallback |
| Save/skip/confirm/accept/reject | deterministic, no AI | validation, revision fence, persistence | Worker/Supabase/editor |

Strict structured schemas and domain validation treat document instructions as data; no tools or external URLs are enabled. Output token limits are admission 300, extraction 8,000, questions/rewrite 1,800. Attempts use 8 seconds for admission or 25 seconds otherwise, bounded by 30 seconds total per stage; the outer operation is 90 seconds and upload body reading 15 seconds. These are limits, not latency promises. One documented availability fallback is permitted for PDF/career; refusals, malformed output, invalid evidence, auth/policy errors and cancellation stop. Word uses documented direct `/v1/responses` input-file support for DOC/DOCX, with no assumed Chat Completions/Router Word support and no extra fallback.

No final prompts/models/prices are silently selected. Amounts are deferred; bounded tokens/time/attempts are not a monetary quota. Each attempt records usage and reported cost if available; missing prices, timeouts and abandoned requests retain unknown cost rather than zero. Both stages can incur charges; cancellation cannot undo them. Native PDF engines/provider model compatibility, access and actual quality are account-dependent and unverified without authorized live calls.

## Optional reasoning effort

`AI_REASONING_EFFORT` is a server-only optional Worker binding shared by admission, extraction, career questions/rewrites and the existing enhancement route. Omit the binding to preserve the existing provider defaults and request/fingerprint shape. When set, use exactly one of `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`; empty, padded, case-changed and other values fail configuration validation before dispatch. There is no client override. The resolved value is snapshotted and recorded as configuration in the opaque attempt fingerprint, without CV text.

OpenRouter Chat receives `reasoning: {effort: value}`, direct OpenAI Chat receives `reasoning_effort: value`, and Word Responses receives `reasoning: {effort: value}`. `none` is sent literally. Operators must verify compatibility for every configured primary/fallback/stage model and provider endpoint: the accepted vocabulary is not a promise that each model supports every value. [OpenAI reasoning documentation](https://developers.openai.com/api/docs/guides/reasoning) describes model-dependent support; [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) supports `none` through `max` except `minimal`, while [OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) documents its effort mapping. This does not establish account ZDR entitlement, latency or extraction quality.

For isolated owner setup, set `AI_REASONING_EFFORT=none` or `AI_REASONING_EFFORT=low` only after verifying the chosen models support it. The existing model bindings remain `OPENROUTER_MODEL`, `OPENAI_MODEL`, `OPENROUTER_CV_ADMISSION_MODEL`, `OPENROUTER_CV_EXTRACTION_MODEL`, `OPENAI_CV_ADMISSION_MODEL`, `OPENAI_CV_EXTRACTION_MODEL`; routing remains `OPENROUTER_ENDPOINT`. Effort does not enable `AI_PAID_INFERENCE`. Output caps remain 300/8000/1800 tokens, admission attempts 8 seconds, other structured attempts 25 seconds, and total stage execution 30 seconds. Privacy guards, replay handling, cancellation and unknown-cost accounting are unchanged. Follow the owner runbook for any later paid evaluation.

## Original source review

The incremental `20261029060000_p4_import_source_review.sql` migration adds owner/tenant-scoped retrieval for ready, unexpired original sources and aligns job-editor fact projection and eligibility with sourced section headings and the [editor acceptance rule](#customer-journey-and-saved-truth). It must be reviewed and applied through the normal authorized migration process before source preview works in a deployed environment. This change does not apply a cloud migration. The Worker uses the verified user token and private bucket RLS, never a signed/public source URL; responses are private/no-store. PDF responses are attachments; the Word response contract is described below. Account/session fences apply to the new route as to other authenticated reads.

The browser verifies original bytes against the extraction SHA-256 before rendering with pinned PDF.js. Worker, fonts, CMaps and decoder resources are bundled locally. Selecting a review field opens its original page; source-text bounding boxes follow page rotation, zoom and crop coordinates. Boxes are available only for unique complete-run quote matches with source font metrics. Native partial/ambiguous/unmatched quotes use the selected-page local OCR fallback described below. Neither model rectangles nor generated CV highlights substitute for source evidence. Scan extraction remains on the existing import path; local OCR supplies independently image-derived word geometry after review opens. Word originals use the same authenticated, ready/unexpired owner lookup. The source endpoint returns source-hash-verified bounded DOC/DOCX extracted text as private no-store JSON. DOCX text uses the existing bounded XML reader; DOC uses bounded text pieces from its Word streams. The view is labelled extracted text, with unique quote matches highlighted and missing/ambiguous matches explicitly unlocated. It renders escaped plain text, makes no Word-layout or pagination claim, and makes no conversion-service or extra provider request. Source/account replacement and disposal abort the view request and discard late results. Expired sources show a retryable unavailable state under the existing retention rules.

Focused synthetic tests exercise digital PDF rendering/coordinates at four rotations and two zoom levels, scanned PDF fallback, section editing/progression/history/categories, source retry and route/account/storage fences. Native PostgreSQL source-access tests are included; execution requires the existing local PostgreSQL binaries. Browser bridge availability and native SQL execution must be recorded separately from unit/build results; they are not implied by passing tests.

### Bounded local scan fallback

When native PDF text cannot locate the selected quote, the browser lazily loads a single local Tesseract.js 6.0.1 worker with the compatible pinned 6.1.2 LSTM core. Only the selected source page is rasterized (maximum 1600×2400 and four million pixels); no whole-document OCR delays import completion. The compact integer `4.0.0_best_int` Romanian and English models from the pinned 1.0.0 language packages are bundled alongside the embedded-WASM core, worker and license notices in `/licenses/`. Romanian-first multilingual recognition preserves accents in the synthetic mixed-language fixture; no accent-stripping or fuzzy matching is used to force a match.

OCR rectangles come from recognized words in the actual source raster, mapped back through its PDF viewport and into the displayed zoom/rotation. Highlighting requires a unique normalized quote/token match and every matched word confidence at least 70. OCR matching is labeled separately from an exact native PDF text match. Ambiguous, low-confidence, unreadable, unsupported-language or unmatched text remains explicitly unlocated; OCR is not universal recognition or semantic verification. Word originals still have no PDF page preview.

The worker is immediately cancellable during initialization or recognition, has a 45-second job deadline, and keeps at most two source-page results (maximum 4000 words each) in memory. Page changes cancel active work; source/account changes and unmount dispose the worker and clear results. Only hash-verified original bytes reach rendering/OCR. No original bytes or recognition results are sent to a service or written to IndexedDB/localStorage; language resources are passed as explicit local bytes, disabling the library's default CDN/cache paths. Retry clears that page's in-memory result. Static model assets may use ordinary HTTP asset caching.

The actual shipped browser worker and embedded core run in the existing Node test harness with external networking and persistent model caching denied, against a synthetic image-only PDF. Tests locate English/Romanian source glyphs, check OCR pixel boxes and their four view rotations/three zoom scales, reject duplicate/absent quotes, exercise bounded reuse, and terminate during initialization and recognition. This proves engine/protocol/geometry behavior, not browser layout or browser CPU/memory performance. UI lifecycle tests separately cover account/source replacement, stale-result rejection and retry.
