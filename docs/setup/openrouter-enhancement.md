# OpenRouter primary / direct OpenAI fallback: offline groundwork

Prepared 2026-10-28. **Live CV generation remains disabled. Neither route is proven strict EU-only.** This is a technical readiness assessment for owner review, not a compliance certification. Nothing was deployed, enabled, purchased or sent for inference. No existing secret values were read.

## Existing flow and chosen boundary

The Base CV editor currently uses manual enrichment. `apps/web/src/base/enrichment.ts` saves an answer into a source, requires explicit confirmation and separately adds/removes its CV contribution. `Fact` records distinguish extracted/unconfirmed, authored and confirmed content; `Answer` has its own state. The editor source lineage survives edits. These contracts and the manual UI remain unchanged.

The earlier OpenAI/admin groundwork provides a fixed connection check in `apps/api/src/ai/openai.ts`, normalized numeric usage, immutable price snapshots, an abstract `UsageLedger`, and a synthetic admin preview. Its global fixed-prompt connection check is **not** an EU-approved CV route. The production Worker does not construct the enhancement adapter. No durable AI ledger or enhancement HTTP endpoint has been added.

`prepareEnhancement` in `apps/api/src/ai/enhancement.ts` is a small internal Chat Completions rehearsal, sharing the existing ledger rather than adding an SDK/framework. It accepts explicit routes/models, scoped context and an injected transport; the only executable mode is `synthetic` with a synthetic ledger. Default, misspelled and attempted `live` modes reject before transport. There is no secret parameter, ambient environment access, default fetch, runtime enable flag or approval capable of activating live generation. The example fixture is disabled with no evidence/model selection.

`projectEnhancementContext` selects only the target role's context/bullets or a supported optional entry's details/bullets, plus confirmed answers for that target. A linked answer is deduplicated only when an eligible authored or confirmed CV field matches its field ID, exact answer text and source ID. Revised answers and answers whose linked fields were independently edited, removed or remain unconfirmed are retained; source lineage alone does not establish a match. This boundary is covered for roles and supported optional entries in [the enhancement checks](../../apps/api/tests/enhancement.test.mjs). The projection excludes identity, contacts, locations, company names, whole documents, raw source text, other roles, unconfirmed facts and job text. The future caller must first verify draft ownership and privacy suitability. Scoped free text can still contain personal/sensitive information: this projection is **not anonymization or a PII classifier**. Synthetic mode must use invented content only.

The provider sees opaque fact IDs and necessary fact text; source references stay server-side. CV/job text is untrusted data, separated from fixed instructions. Output returns an independent `status: proposal` object with unchanged source references; it never edits a draft, confirms an answer or creates a fact. For this groundwork the truth guard accepts only an exact quotation of one supplied fact. Invented experience/metrics and unsupported references reject. Useful paraphrasing and semantic entailment validation remain future work; source IDs alone cannot establish truth. Jobs/history have no dependency on this rehearsal.

## Bounded provider flow and accounting

1. Validate strict EU evidence for both configured routes before reserving any attempt. Unapproved primary does not cause a jump to fallback. Recheck approval expiry before each attempt.
2. Reserve an attempt in the existing ledger. OpenRouter is primary; optional direct OpenAI is the sole fallback. They share `operationId`, have different attempt IDs and separate provider scopes. Replay returns reserved metadata without another request/proposal; failed settlement propagates before fallback.
3. Synthetic requests use only fixed regional endpoint URLs, manual redirects, no streaming/tools/plugins/model router, bounded input/output/response size and a total deadline. OpenRouter pins one endpoint slug, disables its internal fallbacks, requires parameters and requests no collection/ZDR. These controls constrain routing; they do **not** prove EU-only processing. [Provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)
4. Allow at most one fallback for transport failure, attempt timeout with time remaining, or a bare 502/503/504 response without a provider error/refusal. Unknown or structured provider errors (even 5xx), quota/credit/auth/validation/region errors, refusals, redirects, malformed/truncated output and truth failures stop. This intentionally conservative classification leaves some genuine transient failures unrecovered. Provider cancellation is best effort; a timed-out primary may finish and accrue cost. Both the fetch and body read are bounded, including synthetic transports that ignore abort. Total budget exhaustion or caller abort prevents fallback. There is no retry/backoff loop. [OpenRouter errors](https://openrouter.ai/docs/api_reference/errors-and-debugging)
5. Record only safe IDs/statuses, requested/resolved model, reported upstream provider, evidence reference and allowlisted numeric usage. No prompt, response text, raw error, headers or credential is logged or persisted. The fingerprint contains opaque references/configuration, never CV text or its hash. Future durable idempotency must bind a verified draft revision and operation reservation; opaque IDs alone are not sufficient for changed draft content.

The existing ledger now accepts `openrouter` and optional upstream/evidence/reported-cost fields. Chat usage maps prompt/completion and cached/reasoning detail into existing counters; absent cache detail stays unknown, not zero. Provider-reported OpenRouter `usage.cost` is retained separately from estimates, with source and observation timestamp; duplicate deliveries with conflicting reported charges reject in the synthetic ledger. Credits are USD-denominated. Positive values finer than nano-USD or unsupported numeric forms stay unknown. No extra generation lookup is made. [Usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting), [credit denomination](https://openrouter.ai/support)

Known subtotals prefer the reported request charge, otherwise the existing estimate; they never add both. Every distinct attempt can contribute usage, including failed truth validation. Missing/invalid usage, missing prices and timeout costs remain separately unknown. Router request charges exclude the credit-purchase fee and any separately invoiced BYOK provider charges; they are not all-in spend or invoice reconciliation. BYOK is not proposed here: the fallback key is used **directly**, never uploaded to OpenRouter. [Pricing/fees](https://openrouter.ai/pricing)

No direct regional price estimate is applied: existing global OpenAI standard fixtures omit regional surcharges and must not price this route. No historical price snapshot was changed. Durable AI storage, real admin aggregation/rendering of the new fields, quotas and monetary budget enforcement remain unconnected. Future integration must reserve a worst-case budget for **two** attempts, retain unknown primary liability, and stop when either account or total budget cannot be established. Defaults here (12 seconds total, 5 per attempt, 256 output tokens) are synthetic rehearsal limits, not measured production settings.
