Define validated CV content, its field and list limits, and item traversal and visibility helpers.

- Limits are 256 KiB serialized CV bytes, 40 list items, 20 bullets, 2,000 short-text characters, 4,000 long-text characters, two titles and ten achievements. `packages/shared/src/cv.ts:5` -> `MAX_CV_BYTES`
- IDs require 1–64 characters; dates allow empty, four-digit year, or year-month with month 01–12, without date chronology checks. `packages/shared/src/cv.ts:18` -> `const id`, `packages/shared/src/cv.ts:23` -> `regex`
- Notes allow 25 without jobId and 25 with jobId independently, defaulting to an empty list. `packages/shared/src/cv.ts:57` -> `notes:`; A note has a nonempty 1–3-element pick/type/voice array, an ISO timestamp and optional UUID jobId; question and answer use short/long text limits. `packages/shared/src/cv.ts:28` -> `NoteSchema`
- Role facts are strict, allow at most eight 160-character items, and carry a source string plus ISO timestamp. `packages/shared/src/cv.ts:40` -> `RoleFactsSchema`; Experience, education, skills, languages and certifications reject extra fields; role descriptions use the long-text limit and bullets the bullet limit. `packages/shared/src/cv.ts:55` -> `description:`, `packages/shared/src/cv.ts:67` -> `EducationSchema`, `packages/shared/src/cv.ts:79` -> `SkillSchema`, `packages/shared/src/cv.ts:90` -> `LanguageSchema`
- SkillGroup and SKILL_GROUPS keep technicalSkills, professionalSkills and unclearSkills separate and in that order. `packages/shared/src/cv.ts:87` -> `SkillGroup`; CV list fields independently use the 40-item limit, including each of the three skill groups. `packages/shared/src/cv.ts:182` -> `experience:`
- Legacy projects are detected by name without title; conversion creates stable project-id-derived bullet IDs, caps bullets and clips the final combined overflow bullet. `packages/shared/src/cv.ts:104` -> `legacyProject`, `packages/shared/src/cv.ts:113` -> `bullets:`; Projects validate as strict experience plus url after legacy conversion. `packages/shared/src/cv.ts:121` -> `ProjectSchema`
- Basics text fields do not validate email or URL syntax; optional nullable photo metadata limits path to 300 characters, crop coordinates to 0–100 and zoom to 1–3. `packages/shared/src/cv.ts:135` -> `email:`, `packages/shared/src/cv.ts:141` -> `photo:`
- Awards, courses, publications and interests support optional hidden flags and optional bullet lists capped at 20. `packages/shared/src/cv.ts:153` -> `const lines`, `packages/shared/src/cv.ts:156` -> `AwardSchema`; withoutHidden removes hidden awards/courses/publications/interests only, and returns the original CV object when no list changes. `packages/shared/src/cv.ts:283` -> `withoutHidden`
- Layout validates known section keys and maximum list lengths, but does not enforce uniqueness or completeness; defaultLayout copies all section keys. `packages/shared/src/cv.ts:166` -> `LayoutSchema`, `packages/shared/src/cv.ts:175` -> `defaultLayout`
- Current content requires literal schemaVersion 2 and layout, defaults enrichedAt to null, and rejects extra fields; v1 remains separately expressible. `packages/shared/src/cv.ts:194` -> `CvContentV1Schema`, `packages/shared/src/cv.ts:196` -> `CvContentSchema`, `packages/shared/src/cv.ts:208` -> `enrichedAt:`
- emptyCv defaults to English, blank basics, empty collections, default layout and null enrichment timestamp; newId uses crypto.randomUUID. `packages/shared/src/cv.ts:225` -> `newId`, `packages/shared/src/cv.ts:229` -> `emptyCv`, `packages/shared/src/cv.ts:255` -> `achievements:`
- scoredItems visits experience, then projects, then volunteering; findScored returns the first matching ID in that order. `packages/shared/src/cv.ts:270` -> `scoredItems`, `packages/shared/src/cv.ts:278` -> `findScored`

## Assumptions

- Parsing a CV checks shape, not ownership; API authentication establishes the user before CV routing: `apps/api/src/app.ts:68` -> `verifyToken`, `apps/api/src/app.ts:74` -> `/v1/cv`.
- Helpers rely on IDs identifying the intended item; the schema bounds each ID but findScored chooses the first match without a uniqueness check: `packages/shared/src/cv.ts:18` -> `const id`, `packages/shared/src/cv.ts:279` -> `find`.
- Photo path validation does not establish access rights; storage access relies on the bucket's user-folder policy: `packages/shared/src/cv.ts:142` -> `path:`; `supabase/migrations/20261108030000_cv_photos.sql:7` -> `auth.uid`.
