# Resumora — audit (4 Nov 2026, commit 86f99fd)

## Verdict
The product idea and some foundations are good (shared contracts package, strict JSON-schema model output,
cookie + CSRF auth, RLS, no service-role key in the browser). But the codebase has been built like a
distributed financial ledger, not a CV app. About half of the effort goes into protecting against race
conditions that a one-CV-per-user product barely has, and that machinery is now the main source of
fragility and of agent confusion.

## What I ran (Windows, Node 22.14)
- `npm ci` fails out of the box: `engine-strict` + a dep requiring Node ≥22.22. Works with `--engine-strict=false`.
- `npm run typecheck`: passes.
- Web tests: 848/848 pass (3 minutes).
- API tests: 458/459 — `source-location.test.mjs` fails on Windows (pdfjs font path `/C:/...`). The suite only passes on the original WSL machine.
- Dev startup (`dev:start`, `dev:doctor`) needs Linux systemd; not usable on Windows/macOS.

## Confirmed bugs / reliability risks
1. **Strict model-name check** — `apps/api/src/ai/enhancement.ts:577`: response is rejected as `OUTPUT_INVALID` if `modelResolved !== route.model`. Providers often return a dated snapshot name (e.g. `gpt-4o-mini-2024-07-18`). If the configured name is an alias, every call fails — and this error does not trigger fallback.
2. **Narrow fallback** — only 502/503/504/timeout fall back (`enhancement.ts:569`). 429 rate limits, bad JSON and refusals end the operation immediately.
3. **Errors swallowed** — `apps/api/src/index.ts:155` turns any exception into a bare 503 with no log; ~39 empty `catch {}` in `apps/api/src`. Production failures will be invisible.
4. **Stuck imports** — `import-processor.ts:174`: "Interrupted/unknown work is never re-queued." A worker crash leaves the user stuck; they must re-upload. Timeouts are duplicated in TS and SQL and already drifted once (120s → 420s patch migration).
5. **"Save before AI" gate** — `App.tsx` throws `SAVE_REQUIRED` in 6 places unless the draft exactly equals the last save. With a 650 ms autosave, AI buttons feel randomly disabled while typing.
6. **Side effects during render** — `App.tsx:144-151` subscribes to the controller during render and never unsubscribes; refs and controller state are mutated during render in several places. No ESLint / `react-hooks` rule exists to catch stale closures.
7. **Storage growth** — `editor_draft_snapshots` is append-only (DELETE blocked by trigger); every autosave writes the full CV (up to 1 MiB).
8. **Uploads stored as base64 in Postgres** (up to 13 MB per row) instead of Supabase Storage.
9. **Skills improvement locks the whole profile** for up to 90 s, then says the attempt was discarded.

## Over-engineering (what to remove)
- **DB**: "canonical publication" graph never written by the API (`claims`, `claim_provenance`, `entity_revisions*`, `profile_versions*`, `cv_versions/sections/items`, `source_spans`, `evidence_*`), `tenants` / `tenant_memberships` for single-user accounts, per-attempt AI ledger + settlements + reservations + leases. Migrations patch earlier functions by string-replacing `pg_get_functiondef` output.
- **Frontend**: three generations of enrichment UI side by side (`ExperienceEnrichment` 1.6k + `ExperienceDetailPanel`, `GuidedExperience` + `useGuidedExperience` 1.4k, `Enrichment` + `AiSuggestions` + `RoleRewrite` 2.3k). Dead: `LiveDictation.tsx`, non-embedded editor mode, old flat routes / `HomeScreen` / `StartChooser`, `mara-review.ts` demo data. ~6–7k lines removable plus ~8k lines of tests guarding them.
- **Client-side distributed systems**: 90 s deadlines enforced twice, operation IDs, receipts, BroadcastChannel removal fences, cross-tab CSRF fencing.
- **Tooling/docs**: ~1,100 lines of systemd dev tooling (half of it tests of itself), `PROPOSAL-MANIFEST.sha256` (107 of 118 listed files no longer exist), circular docs (README → SETUP_GUIDE → environment.md → local-development.md), `docs/archive`, `research/`, `references/`, unread `--receipt` CI output.
- **Tests**: ~18 files named `*-regressions` / `*-recovery` / `*-fencing`; they lock in the complex behaviour and make it expensive to simplify.

## Worth keeping
`packages/contracts` (types + validators), strict `json_schema` model output + validation, prompt versioning,
HttpOnly sealed session cookies + CSRF/Origin check, RLS with `search_path=''`, the import flow concept
(upload → admit → extract → review), accessibility work, design tokens in `design/*.css`.

## Impact on the job-tailoring feature
A job product (jobs, requirements, match evidence, readiness, browser-extension capture pairing, tailored
editor documents) **already existed and was deleted**. The removal migration now actively forbids it:
`CHECK (document_kind='base')` (line 1276), CHECKs rejecting any `jobId` in snapshot JSON, schema
`context.kind: const "base"`, locale only `ro|en`. Every field is wrapped in a `Fact` with status/source/lineage,
which makes diffs and tailoring verbose.

Target model:
```
base_cv        (user_id PK, content jsonb, updated_at, version int)
base_cv_history(id, user_id, content jsonb, created_at)          -- capped, e.g. last 30
jobs           (id, user_id, url, title, company, description, captured_at)
tailored_cvs   (id, user_id, job_id, base_version, content jsonb, score jsonb, created_at)
cv_imports     (id, user_id, storage_path, status, error, result jsonb, attempts, updated_at)
ai_calls       (id, user_id, kind, model, ms, tokens, status, error, created_at)
```
Stable `id`s on every experience/bullet (mostly already present) make "tailored vs base" diffs easy.

## Recommended plan
**Phase 0 — stop the bleeding (1–2 days)**
- Fix model-name check; widen retry/fallback (429, invalid JSON); log every caught error with a request id.
- Re-queue interrupted imports (max N attempts); single source of truth for timeouts.
- Replace AGENTS.md with a short, plain-language guide; delete manifest/archive/dead tooling; make `npm run dev` the one way to start; add `.dev.vars.example`; drop `engine-strict` or align `.nvmrc`.

**Phase 1 — simplify the core (1–2 weeks)**
- Squash 39 migrations into one baseline schema (above). Move uploads to Supabase Storage. Cap history.
- Backend: one `callModel(schema, prompt)` (~150 lines) replacing `configured.ts` + `enhancement.ts` ledger; prompts in `prompts/*.ts`; route table instead of nested ternaries.
- Frontend: add ESLint + react-hooks; extract `useDocument` (load/save/undo/history) from `CvEditor`; React Router + TanStack Query; send the current draft with AI requests (drop SAVE_REQUIRED, deadlines, receipts); one enrichment flow, delete the other two.
- Tests: keep ~100 behavioural journey tests; delete race-permutation tests along with the code they protect.

**Phase 2 — UX**
- One "Improve with AI" per role → a single panel (questions → proposal → accept / keep mine).
- Skills improvement as a non-blocking suggestion list.
- Score as a hint, not a gate. Rename "Base CV" → "My CV"; drop "checkpoint" / "provenance" wording; move copy to a message catalogue.

**Phase 3 — job tailoring**
- `jobs` + `tailored_cvs`; extension posts job page text to `/v1/jobs`; small model extracts requirements, scores, proposes edits as a diff against the base; user accepts per item; export.
