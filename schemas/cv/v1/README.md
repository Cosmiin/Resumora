# Canonical CV schema v1.0.0

Discovery-only proposal. JSON Schema2020-12 is generated by `build_fixtures.py`; `schema.json` is the versioned contract, not a production database migration. It covers all canonical sections, two independent title slots, contact export policy, professional/technical skills, employment/accomplishments/metrics, education, optional/custom entries, structured enrichment, claim links, provenance, interviews, generated prose and document order. Tenant IDs and private object keys are deliberately absent from the portable CV content projection; server envelopes enforce ownership.

Run from the repository root (Python3, jsonschema>=4.10; version4.10.3 used):

```sh
python3 schemas/cv/v1/validate.py
```

Fixtures: `minimal.json` (name only, optional sections absent, null title slots); `full-ro.json` (two titles, ongoing/overlapping/year-only dates, all optional kinds, private address, generated approved/pending wording, interview/provenance); `tailored-en.json` (Base/job lineage, English document language, projects moved independently and unconfirmed certification hidden).

Additional `journey-mara-base1.json`, `journey-mara-base2.json`, `journey-mara-jobcv1.json` and `journey-mara-jobcv2.json` fixtures capture the shared Mara case.

The validator checks referential integrity beyond Schema and rejects15 deliberate invalid variants. Confirmation does not prove real-world truth; external verification needs a separate method. IDs are unique within snapshots, claim content immutable across versions; changed claims receive new IDs. `targetEntityId` supports structured enrichment without overloading generated prose as factual source. Schema version migration/DB normalization are in `research/architecture/data-model.md`.

A draft snapshot can contain unconfirmed facts for review. Export eligibility is stricter: only selected confirmed fields and approved supported prose; private contacts excluded; unconfirmed, suggested or rejected content cannot be exported as attested facts without a later confirmation. Full production export projection and adversarial security tests remain implementation work.

## Assessment companion added after review round1

Canonical CV schema1.0.0 remains unchanged. `assessment-input-1.1.schema.json` separately pins profile/document/job/requirements/rules/matcher/dictionary/as-of,requirement category/priority/hard-gate/polarity,accepted evidence class and provenance-bearing confirmed-unmet assertions. `validate_assessment.py` checks5synthetic evaluations and rejects3invalid variants. It does not certify natural-language extraction or real-world truth. Current scoring is `research/ats/score_v1_1.py`; method1.0 remains archived.

## Workspace companions

`journey-workspace.schema.json` and its Mara fixture describe the discovery application/contact/next-action/LinkedIn workspace, generated by `build_workspace_fixture.py`. The v1.1 companion and fixture, plus `workspace-query-worked-v1.json`, are generated by `workspace_revision_v1_1.py`; this script also exercises latest completed CV, tailoring provenance, search and explicit sent-record semantics. These are separate from canonical CV validation. See the [journey contract](../../../research/architecture/journey-contracts-v3.md) for their proposed production invariants.
