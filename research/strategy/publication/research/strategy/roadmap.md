# Journey-based roadmap — iteration 2 proposal

2026-10-23. An ordering recommendation, not a schedule or implementation authorization. Owner-added applications/readiness/LinkedIn/capture aims stay in discovery. [Release options](iteration2/release-options.md), [current backlog](../../docs/product/implementation-backlog.md), [decision register](../../docs/product/decisions.md).

| Stage | User outcome | Evidence needed before progressing |
|---|---|---|
| Current integrated discovery | Owner understands the journey, tries realistic edits and sees consequential alternatives | One UX entry; shared Mara/job/version fixture; desktop/mobile end-to-end evidence; exact feedback dispositions and scoped decisions |
| Foundation, only after approval | Correct/save a structured Base, get immediate useful advice and recover from import failure | Provenance/version/date/undo cases; account privacy; deterministic diagnosis and progressive question contract; bounded runtime feasibility |
| Core application loop | Review a job, enrich truthfully, approve a specific CV, export and return to the application | Matching/eligibility/readability separation; bilingual/negation/credential fixtures; full-size PDF/text-order checks; latest-versus-submitted history, search and sent-count cases |
| Bounded pilot, if approved | Exercise R-A's chosen capture, LinkedIn, readiness and application depth with recoverable quotas | Explicit acceptance corpus, privacy/access/budget decisions; expanded operation costs and real workload/latency/quality measurements; no zero-cost promise |
| Broader release, if approved | Clear account, 1/3/6-month term concept and useful continuity with known operating limits | Actual entitlements/cancellation/recovery tests, professionally reviewed terms, support and spend model; no selling price selected by strategy |
| Post-MVP expansion | Add convenience where observed friction/demand justifies it | Broader capture sites/LinkedIn import, reminders, OCR/DOCX export, more layouts, aliases/languages or adjacent documents each need their own evidence and maintenance budget |

Requested capture is not automatically post-MVP. R-C would stage its breadth only after an explicit owner decision and named milestone. New templates require extraction/reading-order checks; new languages need term/negation/qualification evidence; deeper capture requires permissions and correction/fallback; OCR requires confidence/correction and a cost bound. No autonomous applications, employer ATS equivalence or interview-probability promises.
