## Migrations, rollout and rollback

SQLmigrations are versioned,reviewed,rehearsed on synthetic staging andbacked up. Expand→backfill→verify→switch→contract ratherthan destructive same-release rename/drop. Old/new readers coexist during rollout;immutableCVschema/rules/templates remain pinned. Backfill checks count,tenant,lineage andhash consistency;pause switch on mismatch. Separate feature flags foruploadparser,URLingest,newscorer,newmodel,template andbillingprojection. Migration approval is human-controlled;AI proposes andexplains,but doesnot run irreversible changes unattended.

Roll forward data fixes where rollback would destroy newer user edits. Keep lastcompatibleapplicationimage,old rules/templates/fonts andDBschema reader;revert deployment/featureflags independently. Do not replaybilling sideeffects duringrollback/restore;eventIDs/idempotency survive. Restoring aDBbackup alone is insufficient:restoreobjects/manifests andapplydeletiontombstones,thenreconcileauthoritativebilling before grantingaccess. Define reviewed incidentrunbooks forcredentialleak,cross-tenantread,provideroutage,runawayspend,renderfailure andcorruptmigration.
