# OpenAI first, provider/OpenRouter adapter later — discovery contract

Review round1 authorizes this architecture revision, not production integration or paid experiments. Start direct OpenAI using an approved model/endpoint/data policy. Domain modules depend on a small structured generation/matching port; they do not depend on router-specific SDK objects or allow models to set final scores.

Request contract: operation,tenant/operation IDs,selected confirmed evidence/requirements,locale,prompt/schema version,approved model/routing policy,max input/output/reasoning tokens,timeout,region policy and idempotency metadata. Response: proposed structured requirements/evidence/prose,validation errors,provider request ID,requested/resolved model,actual upstream provider,usage and billing provenance. Stream tokens may improve UX but only validated complete output can be accepted into facts/mappings. No raw source PII in meter logs.

DirectOpenAI is initial adapter. LaterOpenRouter is an alternative adapter behind the same port,not a new mandatory dependency. Record router request ID **and** upstream provider/model/endpoint,quantization/context/pricing mode where reported,router/upstream reported usage,estimated versus actual billed costs/currency/fee schedule and data-policy version. Unknown upstream usage or router fee stays unknown. No assumption that router prices/cache/tokenization equal directOpenAI. Re-run authorized synthetic quality/cost/contract regressions before switching; deterministic scores replay accepted mappings regardless of the original model.

Allowlist approved providers/endpoints/models; disable unapproved fallbacks. Require structured-output parameter support,approved retention/training policy and applicable region. A provider outage may queue/fail safely instead of transferring private CVs to another region. OpenRouter's current routing/docs support these controls,but upstream provider terms and router metadata records remain separate. ItsEurope routing is not automatically strictEU-only and current eligibility can require a paid plan. Keep input/output logging off unless specifically justified/approved; minimize PII before either adapter.

First implementation can use one provider and a handful of adapter methods. No orchestration framework,multi-agentservice or runtime auto-model marketplace needed. Secrets stay server-side; quotas/spend ceilings apply before each attempt. Hard total/model usage caps,timed retries andunknown-cost reconciliation prevent hiddencosts. All actual prices and operational eligibility must be rechecked when integration is authorized. SourcesE-06/E-27 in sources.md.
