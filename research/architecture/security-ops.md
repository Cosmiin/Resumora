# Security, privacy and operating design v1

Proposed controls and policy options, not a compliance certification. Source IDs resolve in [sources](sources.md). Strict EU-only processing, retention schedule and contractual legal basis remain approval dependencies. No production data or accounts used.

## Access, storage and isolation

Default-deny tenant ownership in application services **and** Postgres RLS on every user table/view/private object. Personal account initially maps to auth subject; later workspace membership is a deliberate policy migration. Writes require owner/membership, selected-resource lineage and server-confirmed entitlements. Composite tenant foreign keys prevent cross-tenant references even with known UUIDs. Check SELECT/INSERT/UPDATE/DELETE and storage list/sign/download for two synthetic tenants; views/functions/SECURITY DEFINER paths get explicit search_path and minimum grants. Service-role keys bypass RLS [E-13]; never browser/extension-visible, never used for ordinary requests when user-scoped DB execution suffices. Worker service identity receives narrow job/result operations with tenant checks and bounded resources, not arbitrary user impersonation.

Private buckets only. Object keys are opaque account-scoped IDs; MIME and filenames sanitized; short signed URLs (proposed5min), no long-lived public exports. Downloads reauthorize and use attachment/content-type headers. No CV content in CDN/shared browser caches (`Cache-Control: private,no-store` for API/download pages). Revoke/purge derived exports on relevant deletion. TLS in transit; provider encryption at rest plus application-encrypted backups; secrets held in platform secret store, rotated by approved process, separate dev/staging/prod keys. Support/admin require MFA, named accounts, audit and expiring least-privilege grants. Financial and infrastructure owner credentials remain human-controlled.

## AI terms and residency

Send minimal selected claims and job excerpts; omit name,address,phone,email and irrelevant sensitive data from generation unless essential and consented. Interview may include sensitive/proprietary details: disclose purposes, allow skip/redaction and avoid requesting protected-characteristic information. No training/fine-tuning with user content by default. Provider adapter enforces approved model/region/endpoint, `store:false` where supported, bounded prompt, disallowed tools and logging redaction.

OpenAI API data is not training input by default, but default abuse logs can retain data up to30days and storage/endpoint exceptions apply [E-06]. `store:false` is not a zero-retention or all-EU guarantee. Regional processing availability and eligibility must be checked for exact model/account; cost model includes10% uplift for selected current OpenAI models [E-04]. Gemini free/paid terms differ [E-09]; do not use free inference for private CV processing. Anthropic regional/retention terms need independent contract review before activation; token price alone never authorizes fallback. No provider switch across jurisdictions without policy/consent review.

Supabase project region controls database/storage location; verify backups, auth email, telemetry, support and subprocessors separately. Cloudflare public static delivery is optional; Worker/Browser Run processing isn't made EU-only by choosing EU object storage. R2 explicitEU jurisdiction covers that object location [E-20]; avoid substituting a location hint. Stripe handles payment data under its own processor/controller terms; no card data enters CV domain. Get DPAs, subprocessor list,SCC/transfer assessment where relevant and processor/deletion guarantees. A strict EU-only requirement can change stack/cost; it remains explicit in decision register.

## GDPR-oriented lifecycle and legal questions

Suggested retention options below are review inputs, not selected policy:

| Data | Proposed bounded default | Rights/deletion handling |
|---|---|---|
| Original uploads / extraction scratch | User may delete after confirmation; provisional30days default for source,24h failed/quarantine and immediate temp cleanup | Preserve provenance locator/hash only as needed; original-source deletion must clearly reduce auditability; purge all derived caches |
| Career facts/versions/jobs | While account active, user controls history; warn after proposed12months inactivity before staged removal | Rectification creates a version; explicit erasure removes/redacts all dependent historical copies. Immutability never overrides erasure |
| Generated drafts/interviews | Same account lifecycle, optional shorter90day unaccepted draft purge | Export user answers/confirmations; avoid keeping full provider payloads unnecessarily |
| Rendered PDF/export URLs | Signed URLs5min, stored derived bytes24h unless explicitly retained | Recreate from approved snapshot when available; erase on request, no public sharing by default |
| Application logs |30days sanitized; security events up to90days if justified | IDs and error codes, not raw text,tokens,CV URLs with query data or personal filenames |
| Daily encrypted backups |7day rolling full equivalent copies modeled | Deleted-account tombstone reapplied on restore; expire backup copies on schedule; cannot promise immediate selective deletion of all backups |
| Billing/usage aggregates | Minimum legally justified records, separated from CV | Romanian/EU statutory retention period and lawful exceptions unknown pending accountant/legal advice; pseudonymize where lawful |

Provide clear notices in Romanian/English: purpose,legal basis,processors/regions,retention,rights and contact. Contract necessity may cover core processing; consent/optional services need separate assessment, no forced bundled marketing consent. User capture approval is product consent, not a complete legal-basis determination. Portability exports canonical JSON,selected originals/versions/confirmations and human-readable content via authenticated short-lived bundle; exclude other users' data and unnecessary internal security secrets. Rights intake reauthenticates proportionately, tracks request/due dates, identifies all stores/processors and communicates completion/exceptions. Proposed internal target30days is a workflow reminder; actual legal response timing/extensions need counsel confirmation [E-16].

Legal review questions: controller/processor roles; special-category data accidentally included in CVs; minors/age of consent; regulated credentials and truthful claims; EU transfer/residency scope; exact retention and backup-erasure notice; automated profiling/transparency; whether GDPR DPIA is appropriate; EU AI Act applicability for a user-controlled writing/compatibility assistant versus employer hiring decisions; copyright/website terms for imports; accessible consumer cancellation/withdrawal rights and renewal disclosures; Romanian invoices/e-Factura/OSS/VAT/B2B reverse charge. These are questions, not legal conclusions.

## Operations for a small business

Use one dashboard of latency/error/queue depth/oldest job/provider failure/token spending/export readability errors/webhook lag/deletion completion and backup health. Log request/operation IDs, phase,duration,versions,status,cost counters; redact source bodies and credentials. Monitor percentiles separately for upload/model/render. Alerts for spend50/80/100% of approved budget,dead-letter growth,webhook reconciliation failures,expired leases,missing backup and cross-tenant authorization events. Threshold amounts and paging schedule need owner approval; provider spend delay remains a risk.

AI may summarize sanitized incidents,triage support,group errors,propose knowledge-base edits,explain costs and draft replies. Human approval required before sending sensitive support content, refunds/credits,price/plan changes,account suspension,deletion,data export to third parties,production migrations,restores,secret rotation,legal notices,bank/payout/tax actions or irreversible operations. AI has read-only scrubbed telemetry by default, no payment/admin/cloud credentials. A user explicitly approving deletion of their own account is the human approval step; unattended admin deletion remains forbidden. Keep approval actor/scope/expiry and execution audit.

Recovery proposal: RPO24h with daily DB+object copies; RTO8h initial business target, unproven until restore exercise. Supabase backups omit file bytes [E-12]; independently copy encrypted objects and manifest/checksums to a separate recovery account/bucket, include schema/rules/templates/font assets and revision index. Seven full-equivalent daily footprints modeled; verify actual snapshot growth. Quarterly sandbox restore verifies login/tenancy/claims/prose/object download/usage/provider-event deduplication; preserve deletion tombstones and avoid replaying live financial effects. PITR/HA improves RPO/RTO at extra unknown cost; not silently assumed. One Node host is a single availability domain; restart/scheduled patching and rebuild from reproducible image are required, failover only after measured business need.
