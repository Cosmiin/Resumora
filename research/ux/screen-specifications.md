# Screen and state specifications v1 — 2026-10-23

Status: integrated discovery draft after phase-2 cross-review; not approved implementation. Evidence IDs reference `evidence-map.md`. **O** means visible in static references, **R** means required by baseline, **P** means proposed target behavior. Static screenshots establish no successful network transition.

## Information architecture and document ownership

Primary navigation: Overview → Create CV → Base CV → Enrich profile → Jobs → Compatibility → Tailor & edit → Templates/preview → Account/plan. A separate review page exposes journeys and product options. Workspace preserves a versioned Base; each job has its own job snapshot and tailored snapshots. Editing changes a local draft. Explicit save/checkpoint, confirmed enrichment, approved tailoring and restore create immutable versions. Undo changes a draft; restore makes a new checkpoint. Template and ordering are presentation, never a rewrite of facts. Two optional positioning titles are separate from historical role titles.

Prototype routes: `home`, `register`, `import`, `review`, `base`, `history`, `interview`, `jobs`, `requirements`, `ats`, `compare`, `jobeditor`, `templates`, `preview`, `plans`, `checkout`, `account`, `guide`. Hash navigation supports browser back. Empty dependent routes provide a start path or synthetic example. All routes are local demo state; where browser sandbox storage is unavailable, state remains in memory until the page closes and the limitation is stated in the demo bar. There is no authentication, extraction, inference, URL fetching, extension, billing, authoritative PDF or backend.

## Fit, document match, eligibility and readability

Architecture owner feedback round 1 requests separate Candidate–Job Fit (complete confirmed profile) and CV–Job Match (selected CV only); do not fabricate the former when profile evidence is unavailable. Eligibility is independent of weighted score, has three states (Requirements satisfied / Needs verification / Confirmed requirement gap), and uses an explicit hard-gate classification rather than treating every “required” phrase as disqualifying. An unverified mandatory item remains Needs verification; Confirmed requirement gap requires evidence that the user does not satisfy it. Persist strict-gap warnings beside score, comparison and export preview. ATS Readability evaluates actual rendered PDF extraction and remains Not tested until measured. The numeric example below is now aligned with architecture v3’s versioned shared fixture; it remains uncalibrated and illustrative. Exact feedback and UX dispositions: `architecture-impact-round1.md`.

## Source and confirmation language

Use “Extras · neconfirmat”, “Confirmat de tine”, “Propunere”, “Respins”, and “Verificat independent” only when that last state has actual external evidence. Synthetic C01–C05 are self-confirmed fixtures, never external verification. Keyword API enum retains the baseline `verified_*` names; UI wording clarifies the confirmation basis. Evidence drawer shows fact ID, source locator/hash/version and scope progressively. Generated prose cites claim IDs and has its own approval. No new numeric results without evidence.

## Structured date rules

Persist `{year:2021,month:null}` or `{year:2021}` as a partial year. Render “2021 — Prezent”, not “ianuarie 2021”. Exact month renders localized month/year. Unknown dates remain unknown. Compare known precision/ranges; do not invent days. Ongoing is explicit, with no end fact. Experience calculation belongs to architecture: interval union, fixed as-of date, lower/upper bounds, no overlapping-role double count; gaps are not score penalties. Prototype validates available year/month order; it does not compute experience totals or schema bounds.

## Desktop and mobile

Desktop ≥1100px: persistent left nav, editor and preview side by side, paired skills/title fields, score + evidence columns. 760–1100px: narrower left nav; content panels stack so text remains readable. ≤760px: horizontal scoped nav, stacked fields/cards, 44px controls, full-width document preview below editor, no horizontal page overflow; dialogs sized to viewport. Preview is a flow document in demo, not A4 pagination. On mobile the user explicitly refreshes preview after editing; production can use a Content/Preview switch and sticky save bar after usability testing.

Manual checks: semantic headings/labels, focus-visible ring, native dialogs, status/alert live regions, text status alongside color, readable contrast, reduced-motion preference. Automated WCAG conformance, screen-reader evaluation, touch-device testing, Safari/Firefox and slow/assistive input remain pending. Default form fields have stable IDs/names; native controls drive local state.

## Proposed navigation/event invariants

- A saved Base is never silently mutated by job editing, section suggestions or translation of a job variant.
- Saving/editing/enrichment invalidates stale analysis; explicit recalc consumes selected versions.
- Wording alone does not add confirmed keyword evidence or score.
- Required missing credentials remain visible with any aggregate, comparison and export preview.
- User cannot confirm extraction/interview or activate simulated checkout without a dedicated acknowledgment.
- Hiding/reordering/renaming affects document presentation; history retains previous facts/content.
- File/URL/extension/model/checkout interactions explicitly state simulation and never imply a connected service.

## Deliberate prototype limits

All job parsing and scores use fixed synthetic fixtures, not freeform analysis. Partial dates are validated but interval union is architecture-owned. Education/certification/language/custom sections use editable text in this mockup; production structured entities are specified in the canonical schema. Job history is a stored snapshot chain concept with latest branch editing, while the visible history screen covers Base only. Translation maps known synthetic text; custom text stays unchanged and requires review. No real PDF, OAuth/extension, accounts, webhook, queues, concurrency or entitlement enforcement. These limits cannot be used to silently drop baseline implementation requirements.
